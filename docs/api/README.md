# API 设计入口

状态：接口设计草案，尚无运行中的接口或 OpenAPI 规范。拟实施的完整路由、请求字段、响应与错误规则见 [系统详细设计第 3、5 节](../design/detailed-design.md)。

| 领域 | 计划职责 |
| --- | --- |
| 身份与权限 | 确认用户、项目访问范围和操作权限 |
| 项目与意图 | 创建项目、确认目标与约束 |
| 素材与上传 | 上传会话、分片与校验、元数据和授权记录 |
| 分析与检索 | 受理分析、状态查询、候选片段与来源区间 |
| 故事与补拍 | 节点、素材覆盖、缺口、任务与用户选择 |
| Agent 与任务 | 依赖、阶段、决策摘要、重试和人工确认 |
| 时间轴与版本 | 编辑草案、差异、锁定校验、确认提交和恢复 |
| 审片与导出 | 问题定位、预览、导出任务与版本产物 |

当前设计已统一项目角色、UUID 标识、整数毫秒区间、游标分页、错误结构、任务状态与 `/api/v1` 前缀，详见配套设计。实现时将这些约定落实为共享 Schema 和 OpenAPI。耗时接口返回任务标识，状态由查询接口与后续 WebSocket 通知提供；上传成功不表示处理成功。

修改请求应包含基准版本、目标、操作和约束，先返回差异草案，由确认动作生成新版本。导出只接受通过校验的版本。确认、恢复、幂等和并发规则须与详细设计及数据库事务保持一致。

FastAPI 工程建立后，在这里记录 OpenAPI 的生成与检查方式，并与 [共享契约](../../packages/contracts/README.md) 保持一致。
