# 评测与证据协议

| 项目 | 内容 |

| 适用范围 | 证据覆盖、补拍闭环、局部重规划、Agent 协作、性能与可靠性 |
| 当前状态 | 正式效果评测设计；第一阶段已有规则/工具验证记录，真实素材和模型效果尚待采集 |

> 这份协议把“创新是否成立”转成可复核的对照。所有阈值是验收目标，不是已达成结果；若数据或资源不满足，报告真实失败和限制。

## 1. 评测问题

| 问题 | 核心指标 | 必须保持一致的条件 |
| --- | --- | --- |
| 素材证据是否减少虚构和无效缺口？ | 覆盖判定 P/R、`uncertain` 率、证据引用有效率、补拍后覆盖率 | 同一 Intent、素材、基础模型和搜索预算 |
| 补拍建议是否可执行并能回写？ | 有效任务率、fulfilled 验证率、无效补拍率、用户处置时间 | 同一可用设备、任务条件和授权 |
| 局部重规划是否安全且更经济？ | 锁定保护率、范围外变化率、影响集合精度、规划 P95、重算片段数 | 同一基准版本、锁定集合、输出质量门槛 |
| 七角色分工是否有额外收益？ | 任务成功率、质量盲评、成本、失败恢复、确认次数 | 相同核心机制、模型、预算和工具权限 |

## 2. 数据集与分组

- 目标为校园、旅行、家庭/朋友、个人 Vlog、小型组织宣传五类场景，每类 3 组任务，每组至少 20 段素材，共 15 组、至少 300 段；这是待建设目标。
- 每场景 1 组用于开发，2 组用于冻结测试；同一事件的原片、裁剪片和近重复片不得跨集合。记录来源授权、设备、地点/时间隔离和无法隔离因素。
- 每组先由用户确认故事节点、必需要求、可略过项、锁定片段和可用替代；两名标注者独立标注候选证据、覆盖状态、缺口类型和可接受修改，分歧由第三人裁决。
- 测试集冻结后不能按结果改节点、分母、阈值或挑选成功样例。缺失、超预算、等待用户、拒绝补拍、失败和无法判断都保留。

## 3. 对照设计：先拆解机制，再比较角色

所有自动方案使用同一确认 Intent、初始 evidence manifest、素材、模型配置、输出规范及调用/金额/墙钟时间上限。记录实际消耗和预算耗尽导致的失败；相同上限不代表调用次数相同。A/B/C 是总体对照，不能直接证明单个机制；每项消融只改变明确的处理环节。

| 编号 | 条件 | 作用与因果边界 |
| --- | --- | --- |
| A | 人工/模板，用户可查看同一素材及备选池；无系统提示 | 测用户任务成本；人工熟练度和可用时间必须记录 |
| B | 基础自动规划；无结构化证据覆盖和补拍指导；无依赖影响传播，但保留锁定校验、权限和最终确认 | 判断整体机制的附加效果；改变多个因素，不能归因于其中一个 |
| C | 覆盖、补拍指导、局部传播、七角色与完整硬校验 | 全流程；所有可执行缺口均提供同样的可用备选池 |
| D1 | C 去除逐项证据核对与覆盖状态计算；其他流程、模型、预算不变 | 测证据闭环；无法自动生成缺口的项目计入失败，不能排除 |
| D1b | C 保留检测，但将补拍卡改为无排序的缺口清单 | 测任务排序/说明；两侧提供相同操作与条件 |
| D2 | C 用全片重规划替代局部影响传播；保持锁定、范围约束和最终校验 | 测局部传播的规划成本及成功率；不牺牲安全边界 |
| D3 | C 用单规划角色替代七职责协作；使用相同覆盖/传播模块、工具、人工门及预算 | 单独测角色分工；记录实际调用数与角色是否被绕过 |

A/B/C 必须完整呈报；D1、D2、D3 均为创新判断的必要对照，D1b 属于任务排序专项。不要将模型角色本身带来的变化归到证据或依赖算法。去除锁定校验只能在隔离的历史样例回放中测漏检，不能对真实项目或发布版本关闭保护。

### 3.1 统一补拍输入与用户实验

固定素材回放实验为每个任务预先准备经过授权的补充素材池，池子中包含可支持目标、质量不足和无关素材，并固定其内容及揭示条件。所有组获得相同可用池与观察机会；C 可给建议，但不能得到其他组没有的素材。记录拿到素材、选择、验证与失败；覆盖状态比较在同一轮次结束时进行。

真实补拍另作独立的用户研究，记录时间、天气、位置、设备、知情同意、不能拍和主动放弃；不能把不同时刻、不同拍摄对象产生的改善直接归因为覆盖算法。活动无法重现时测试照片替代、结构调整及用户略过，不伪造当时事件。

### 3.2 样本分配与冻结

正式运行前冻结任务清单、标注指南、基线实现、提示词、角色和模型配置、预算、预报影响范围、随机种子及评价脚本。开发集可调阈值/排序，测试集只评一次并完整记录；相同事件及其派生片段不可跨集。各方案对同一任务配对，执行与盲评顺序随机化；操作者练习和评委独立性记录在案。15 组任务、10 组冻结测试只是试点规模，按任务报告配对差值和不确定性，不能将片段当成相互独立任务，也不能证明普遍优势或显著性。

## 4. 指标、分母及失败口径

缺口检测的最小单位为 **用户确认要求 + 固定 manifest 下的单个节点**；一个节点只有一个真值 `gap / covered / indeterminate`，每个系统只能输出一次。两名标注者独立判断并由第三人裁决，测试开始前冻结。`indeterminate` 不是 gap 或 covered，单独列为未知真值；报告它的数量和比例，不当作系统胜利。自然缺口、人工移除素材形成的缺口分别报告。

### 4.1 覆盖和缺口

设可判定真值中，真实 gap 数为 `G`、真实 covered 数为 `N`；系统输出缺口包括 `missing / insufficient`：

- `TP` 为真实 gap 且输出缺口；`FP` 为真实 covered 却输出缺口；`FN` 为真实 gap 却输出 covered；`U_gap` 为真实 gap 却输出 uncertain 或无结果。系统超时/失败/未产出也归入无结果并单独列出原因。
- **缺口精确率** = `TP / (TP + FP)`；**保守召回率** = `TP / G`，所以 `U_gap` 不会被丢出召回分母。真实 covered 上的 uncertain、超时及拒绝也分别报告。
- 系统 `uncertain` 比例 = uncertain 节点数 / 全部输入节点数；**决策覆盖率** = 输出 covered、missing 或 insufficient 的节点数 / 全部输入节点数。对不可判定真值，输出是否合理单独审阅，不并入 P/R。
- 分母为 0 时结果标记 `N/A` 并报原始计数；不写 0% 或 100%。同时给出逐场景、节点类型、自然/构造缺口结果和每任务明细。
- **证据引用有效率** = 通过同项目、manifest、分析版本、源时间区间及对象状态核验的引用数 / 系统提供的引用总数。没有提供引用时记 `N/A`，同时报告**必需事实可核验率** = 有至少一个有效且经标注支持的引用的必需事实数 / 全部必需事实数；不能通过不引用获得高分。

处理前冻结原始 `required=true` 的节点集 `R0`。**处理后原始必需节点覆盖率** = R0 中经最终 manifest 的合格证据支持的节点数 / `|R0|`；用户 skipped、降低要求或删除节点仍在 R0 分母，不能自动计为覆盖。另报“经用户确认调整后节点集合覆盖率”，并逐项披露调整与跳过率。目标沿用来源计划的缺口精确率 ≥ 0.80、召回率 ≥ 0.75、处理后覆盖率 ≥ 0.90；原计划未明确原始/调整后分母，此处采用更严格的原始节点口径作实现验收，并同时保留调整后口径以便比较。

**补拍可执行建议率** = 独立评审确认满足已知地点、时间、设备、授权及任务目标的建议数 / 全部提出的补拍建议数；条件未知的建议作为待确认单列，不当作可执行。**验证通过率** = 进入 submitted 且验证结果达到 fulfilled 的任务数 / 已提交任务数；分析失败、超时、持续 submitted 均留在分母。另报用户拒绝、unable、取消、未提交及每类总任务数，防止只统计容易完成的补拍。失败重试在任务级计一次最终状态，并提供每次 attempt 原始记录。

### 4.2 局部修改

对每个基准版本按稳定 `clip_key` 对完整 EDL 规范化，排除数据库行/版本 ID 和创建时间；包含源对象、源/目标区间、track、速度、配置与依赖。删除旧键、添加新键、移动或改变依赖均为变化。

- 未经明确解锁的**锁定保护率** = 规范化摘要不变的锁定基准片段数 / 未明确解锁的锁定基准片段数；目标 100%。无锁定项时为 `N/A`；任何一次未授权变更都为硬失败，不用均值掩盖。
- 先于求解冻结批准集合 `I`，`B` 为基准键集合、`C` 为候选键集合，新增键须在草案中预分配且经过授权；范围外分母为 `(B ∪ C) − I`。**范围外变化率** = 此集合中 added/removed/updated 键数 / 此集合总键数；为 0 时目标为零变化，空分母为 `N/A`。禁止结果出现后再把变更键加入已批准集合；扩大范围需重新授权并保存新报告。
- 实际变化可能少于预报，不能拿 actual diff 当唯一真值惩罚必要的风险预警。另由两名标注者根据操作、冻结约束和依赖标注可接受影响集合：比较预报集合和人工集合的精确率/召回；分别报告预报/实际集合规模、过度扩大、漏报以及无法确定样例。
- **局部计划成功率** = 在预算内生成通过硬校验和授权门槛的候选数 / 全部局部修改请求数；冲突、超时、拒绝扩范围和无可行解均单独列出。合法无解不等于系统缺陷，但仍不能从分母删除。
- 同时报告局部与全片规划 P50/P95、模型调用、计费、重新分析量与人工确认次数。局部规划并不保证局部 MP4 编码，渲染/导出时间单列。

### 4.3 创作质量和用户价值

不少于 3 名盲评者对匿名、随机顺序输出按预先冻结的 5 分量表评价叙事连贯性与基本观看质量；报告评分分布、任务级差异及评委分歧。未产出不能参加成片盲评，但保留在成功率分母，并报告每组盲评可用样本数，不能只比较幸存成片。系统自评分不是盲评。

完成时间从收到任务到确认有效版本或终止，分别记录用户操作、waiting_user、队列、模型、渲染和下载；用户总耗时不得删掉等待。按任务配对比较并提供原始记录；人工工具熟悉度和练习单独登记。

## 5. 可靠性与性能

统一参考负载为最多 30 段、总时长约 10 分钟、输出 120 秒 1080p（功能范围为 60—180 秒）；记录 CPU/GPU/内存、系统、浏览器/真机、模型位置、网络、编码、缓存和代码提交。

| 指标 | 初步目标/口径 |
| --- | --- |
| 本地摄影提示 | P95 ≤ 500 ms；不把云端语义等待计入本地值 |
| 首次故事板 | P95 ≤ 180 s；报告上传后、分析、用户等待和规划的拆分 |
| 等长局部规划 | P95 ≤ 20 s；索引已完成，不含导出 |
| 标准导出 | P95 ≤ 180 s；另报媒体可解码、音画和字幕边界 |
| 锁定/范围错误 | 0；任何一次都需要保留失败样例 |
| 恢复与重复 | 注入至少 10 次中断/网络故障；不得重复提交有效版本 |

性能目标来自需求/执行方案，当前未实测。等待用户不算系统故障，但不能从用户总时长中删除；外部限流、超时和取消均进入可靠性统计。

## 6. 记录格式与发布门槛

每次运行至少记录 `dataset_version`、`task_id`、`scenario`、`code_commit`、`schema_version`、`graph_version`、`prompt_version`、`model_profile`、`random_seed`、`hardware`、`budget`、`timing_boundaries`、`input_manifest_hash`、`approved_impact_hash`、`status`、`failure_code`、`raw_artifact_refs`。原始结果、失败样例、人工决定和配置不得只保留截图。

发布前最低门槛：

1. 证据引用可回到项目内真实素材区间，抽样无跨项目引用。
2. `uncertain`、缺口、补拍和替代状态能在故事板及日志中解释。
3. 锁定保护率 100%，范围外变化率目标 0；出现违规则阻断该草案的版本确认并修复。
4. 对照报告含 A/B/C、D1/D2/D3，给出分母、样本数、失败和限制。
5. 每项“已完成”都能链接到代码提交、数据版本、配置和演示记录；未实测仍标记为待验证。
