## 1. 文档说明

### 1.1 编写目的

本文档将项目原可行方案及前述项目计划转化为可开发、可讨论、可验证的需求清单，为三人团队的原型设计、接口设计、任务分配、集成测试及竞赛材料编写提供统一依据。

文档完整保留原方案的移动端、Web 端、七个功能模块、七类 Agent 和五类应用场景。排期以三人团队在 2026 年 11 月 15 日至 2027 年 1 月 13 日内推进开发为条件；每项需求的完成状态须依据实际代码、运行结果和测试记录填写。

### 1.2 依据与适用范围

编写依据包括：

- 用户提供的《ai影像可行方案》及已经确认的完整功能范围。
- 第二十届全国大学生软件创新大赛项目计划书模板、参赛项目阶段评分标准。
- 当前会话中确认的技术方案、三人分工和六十天开发排期。

本文档作为项目需求基线，侧重“系统应提供什么能力、用户如何使用、完成后如何验收”。技术框架和候选模型沿用原方案；具体接口、数据库字段及模型参数可在详细设计中补充。

### 1.3 术语约定

| 术语 | 含义 |
|---|---|
| 创作项目 | 一次具有独立目标、素材、故事结构、剪辑方案和版本记录的创作任务 |
| 原始素材 | 用户提供的视频、照片和音频文件 |
| 素材片段 | 从原始素材中定位的连续区间，保留文件来源及起止时间 |
| 生活事件 | 结合人物、动作、场景、时间及语音形成的事件描述，如“毕业旅行返程” |
| 结构化创作意图 | 将主题、时长、风格、情绪及特殊要求转换为可校验的创作约束 |
| 故事节点 | 表达某一叙事目标的结构单元，关联情绪、时长及所需素材 |
| 素材覆盖 | 现有素材对故事节点表达目标的支撑情况 |
| 补拍任务 | 为补足某个故事节点而提出的可执行拍摄建议 |
| Agent | 承担特定创作职责的软件角色；不同角色可共享底层模型 |
| 剪辑决策结构 | 用于记录素材来源、时间范围、轨道、转场、字幕和声音配置的自定义 JSON 数据；简称 EDL，不预设兼容外部编辑器标准 |
| 局部重规划 | 根据修改目标及依赖关系重新规划受影响部分，保护未涉及或已锁定的内容 |
| 作品版本 | 一次可追溯的故事与剪辑方案快照，关联预览、导出及修改记录 |

## 2. 项目背景与需求目标

### 2.1 主要问题

用户在校园、旅行、聚会、家庭纪念和个人 Vlog 等场景中能够采集大量影像，但完成作品通常还需要解决以下问题：

1. 拍摄时缺少构图、光线、角度和运镜指导，关键镜头可能遗漏。
2. 素材分散且内容重复，难以根据人物、事件或表达目标找到合适片段。
3. 有素材但缺少故事组织方法，难以形成主题明确、衔接连贯的作品。
4. 缺少对故事完整性的判断，素材不足时不知道应该补拍什么。
5. 修改一个镜头可能影响字幕、旁白和音乐，用户难以控制修改范围。
6. 作品检查依赖反复观看，问题位置和修改依据不够清晰。

上述问题来自场景与任务分析，属于待进一步通过访谈、真实任务和测试验证的需求假设，不作为已经完成的用户调研结论。

### 2.2 项目目标

| 目标编号 | 目标 | 可观察结果 |
|---|---|---|
| GOAL-01 | 帮助用户拍到创作需要的素材 | 有拍摄清单、现场提示和素材回传记录 |
| GOAL-02 | 提高素材组织与查找效率 | 能按自然语言及条件定位相关素材区间 |
| GOAL-03 | 将创作想法转化为可执行方案 | 有可确认的意图、故事板和剪辑决策 |
| GOAL-04 | 发现叙事缺口并提供补充路径 | 缺口能关联节点，补拍任务可理解、可执行 |
| GOAL-05 | 让作品修改可控、可追溯 | 有修改范围、锁定校验、版本对比及恢复 |
| GOAL-06 | 支持完整创作与质量检查 | 能预览导出，定位审片问题并继续修改 |

### 2.3 应用与商业价值假设

项目拟通过减少重复整理、降低基础操作负担、提高素材利用率和修改可控性，为个人记录者和校园组织提供价值。拟探索个人基础使用额度、额外创作服务及小型团队协作服务，具体收费方式需以成本测量、重复使用和支付意愿验证为依据。

本文档不填报未经核实的用户规模、市场份额、营收或效率提升结果。

## 3. 用户画像与应用场景

### 3.1 目标用户

以下画像用于需求设计，不代表已经完成的用户调研统计。

| 用户类型 | 常见任务 | 主要困难 | 重点需求 |
|---|---|---|---|
| 大学生个人用户 | 校园生活、毕业纪念、朋友聚会 | 缺少经验，素材积累多，制作时间有限 | 摄影指导、事件检索、故事规划、便捷修改 |
| 旅行及家庭记录者 | 旅行回顾、生日、节日和家庭纪念 | 素材跨时间与设备，情绪表达较难组织 | 时间与事件检索、故事完整性、声音设计 |
| 个人 Vlog 初学者 | 日常或主题 Vlog | 不清楚应该拍什么，风格和节奏难以稳定 | 拍摄清单、个性化提示、多轨剪辑与局部调整 |
| 社团及学生组织 | 活动回顾、招新宣传、主题纪录 | 多人素材汇总，重点片段难筛选，交付时间紧 | 集中管理、故事板确认、版本对比与审片 |
| 轻量内容创作者 | 主题短片、持续记录 | 重复操作多，希望保留创作控制权 | 自动初稿、可编辑时间轴、锁定与差异查看 |

### 3.2 五类应用场景

| 场景编号 | 场景 | 典型输入 | 期望输出 |
|---|---|---|---|
| SC-01 | 大学生校园生活 | 课堂、运动会、毕业、日常等照片与视频 | 主题明确的校园生活或毕业纪念作品 |
| SC-02 | 旅行影像创作 | 出发、游览、人物互动、返程素材 | 有阶段与情绪变化的旅行短片及补拍建议 |
| SC-03 | 家庭与朋友生活记录 | 聚会、生日、节日、家庭活动素材 | 保留人物与情感重点的纪念作品 |
| SC-04 | 个人 Vlog | 日常拍摄、讲述、环境声和照片 | 可持续调整风格、节奏与声音的个人作品 |
| SC-05 | 社团与活动宣传 | 多人拍摄的活动、采访和宣传信息 | 重点清晰、字幕正确、可按反馈修订的宣传作品 |

### 3.3 系统角色与访问范围

- 项目创建者：创建和管理自己的项目、素材、创作目标与作品版本。
- 经授权的项目参与者：在分配的项目范围内上传素材或参与编辑；具体权限由详细设计确定。
- 系统维护角色：管理运行任务与必要配置，不默认拥有读取用户全部私有素材的业务权限。

项目内角色与七类创作 Agent 分开管理。Agent 的职责范围由任务及工具权限控制，不能自行扩大素材访问范围。

## 4. 产品范围与需求原则

### 4.1 终端范围

| 终端 | 主要能力 |
|---|---|
| Flutter 移动端 | 摄像头拍摄、实时摄影指导、拍摄与补拍清单、素材缓存及上传、语音输入、任务进度、成片预览 |
| Web 创作平台 | 素材库、创意输入、Agent 工作流监控、故事板、多轨时间轴、AI 对话修改、审片、作品与版本管理 |

两端使用同一项目与素材标识。用户在手机补拍的素材应能够进入 Web 端对应项目；Web 端生成的补拍任务和任务状态应能够在移动端查看。

### 4.2 功能范围

1. AI 智能摄影助手。
2. 智能素材管理中心。
3. AI 创意工作台。
4. 多 Agent 智能导演中心。
5. 智能故事板与补拍规划。
6. AI 智能剪辑工作台。
7. AI 审片与作品管理中心。

七类 Agent 为：导演、编剧、视觉、摄影、剪辑、声音、审片。角色职责完整保留，模型实例和部分工具可以复用。

### 4.3 需求与状态原则

- 本文功能表中的要求均纳入本轮完整范围，阶段先后表示开发依赖。
- 需求状态统一为：未开始、进行中、待联调、待验收、已通过、存在限制。
- 当前不依据计划书文字将任何需求预先标记为“已通过”。
- 系统判断应保留来源与不确定性；用户确认、系统分析和预设样例应能区分。
- 用户已确认的锁定条件、必留素材和禁用素材应参与后续规划校验。
- 修改与恢复以版本为依据，不能无记录地覆盖已确认作品。

## 5. 业务流程与使用案例

### 5.1 总体业务流程

~~~mermaid
flowchart TD
    A[创建项目与输入目标] --> B[确认结构化创作意图]
    B --> C[形成初步故事与拍摄清单]
    C --> D[摄影助手指导采集]
    D --> E[上传视频、照片与音频]
    B --> E
    E --> F[素材分析与事件索引]
    F --> G[七类 Agent 协作规划]
    G --> H[故事板与素材覆盖检查]
    H --> I{是否需要补充素材}
    I -->|需要| J[生成补拍任务或替代方案]
    J --> D
    I -->|满足或确认调整| K[生成多轨剪辑方案]
    K --> L[预览与 AI 审片]
    L --> M{用户是否提出修改}
    M -->|是| N[识别范围、校验依赖与锁定]
    N --> O[确认差异并局部重规划]
    O --> K
    M -->|否| P[导出并保存作品版本]
~~~

用户可以先上传已有素材，再确认故事结构；流程不应强制要求先拍摄或先生成完整脚本。

### 5.2 关键使用案例

| 用例编号 | 用例 | 参与者与前置条件 | 主要过程 | 异常及结束条件 |
|---|---|---|---|---|
| UC-01 | 创建并确认创作目标 | 用户已进入可创建项目的状态 | 新建项目，输入文字或语音，设置主题、时长、风格和情绪，确认结构化结果 | 缺少关键信息时补充；目标冲突时展示冲突；确认后形成项目意图版本 |
| UC-02 | 拍摄并上传素材 | 已授权摄像头及必要媒体访问权限 | 查看镜头清单，接收构图、光线和运镜提示，拍摄后缓存并上传 | 权限拒绝时说明处理入口；网络中断时保留本地素材及上传状态 |
| UC-03 | 检索生活事件 | 项目内存在已分析素材 | 输入“去年旅行的海边视频”等查询，结合条件筛选，打开命中区间 | 无结果时给出放宽条件建议；低置信结果可反馈和纠正 |
| UC-04 | 生成故事与补拍计划 | 已确认目标，有可用素材分析结果 | 生成故事节点，匹配素材，检查覆盖，确认补拍卡片 | 无法补拍时选择已有照片、声音或调整结构；不能静默补写真实经历 |
| UC-05 | 查看 Agent 协作 | 已提交创作任务 | 查看角色任务、执行依赖、阶段结果和决策摘要，处理需确认事项 | 模型失败或任务中断时显示原因、可重试范围及恢复位置 |
| UC-06 | 编辑与导出作品 | 有通过格式校验的剪辑方案 | 查看多轨时间轴，调整镜头、字幕、旁白、音乐、环境音和转场，预览并导出 | 素材丢失或时间范围非法时阻止执行并定位问题；完成后关联成片版本 |
| UC-07 | 局部修改 | 已有作品版本，可指定锁定条件 | 提出修改要求，查看受影响内容，确认后生成新版本 | 要求含糊时澄清；与锁定冲突时提供选择；原版本保持可用 |
| UC-08 | 审片与版本恢复 | 已有预览或成片及历史版本 | 查看问题位置与建议，对比版本，选择恢复 | 恢复应生成有来源记录的当前版本，不删除被恢复前的历史 |

## 6. 功能需求

表中“验收要点”是功能可用的判断依据。定量指标与测试口径见第 10、11 章。

### 6.1 基础平台与双端协同

| 需求编号 | 功能要求 | 验收要点 |
|---|---|---|
| FR-SYS-001 | 支持用户身份识别与项目访问控制 | 不同用户不能通过修改项目或素材标识直接访问未授权内容 |
| FR-SYS-002 | 支持项目创建、查看、编辑、归档及删除确认 | 项目状态与数据归属一致；危险操作有明确影响说明 |
| FR-SYS-003 | 移动端与 Web 端访问统一项目数据 | 两端能查看同一项目的素材、拍摄任务、创作状态与作品 |
| FR-SYS-004 | 长时间操作采用任务方式执行 | 提交后返回任务状态；界面不因等待分析或渲染而失去基本操作能力 |
| FR-SYS-005 | 支持上传进度、本地缓存、失败重试及上传恢复 | 模拟中断后可继续或明确重传；未上传素材不被静默丢弃 |
| FR-SYS-006 | 支持任务取消、失败说明与受控重试 | 重试不产生重复版本、重复素材或重复导出记录 |
| FR-SYS-007 | 记录关键操作与处理配置 | 可关联操作时间、任务、项目、代码或服务配置及版本 |
| FR-SYS-008 | 保留可配置的模型与工具适配接口 | 更换候选模型时不要求重写项目、素材和版本业务结构 |

### 6.2 AI 智能摄影助手

| 需求编号 | 功能要求 | 验收要点 |
|---|---|---|
| FR-CAM-001 | 支持摄像头预览、拍照、视频录制和实时画面分析 | 在目标真机完成采集与分析流程，并记录兼容性限制 |
| FR-CAM-002 | 识别人及当前场景，为拍摄提示提供依据 | 提示可对应现场画面；不确定时允许不作肯定判断 |
| FR-CAM-003 | 分析主体位置、画面比例和主体完整性 | 对主体偏移、明显遮挡或截断等样例提供可理解提示 |
| FR-CAM-004 | 分析逆光、曝光不足及光线不均匀等情况 | 分项验证提示有效性，允许用户忽略或关闭提示 |
| FR-CAM-005 | 提供推近、拉远、跟随、平移及拍摄角度建议 | 建议结合场景与目标，不仅显示固定通用文案 |
| FR-CAM-006 | 根据故事需求生成拍摄任务清单 | 每个任务有内容、用途和完成状态，能够对应故事节点 |
| FR-CAM-007 | 根据创作目标与已拍内容提供个性化指导 | 已完成任务可更新，缺少的镜头继续可见，避免重复无效提醒 |
| FR-CAM-008 | 控制提示频率并支持弱网使用 | 基础提示和清单在网络波动时仍可用；云端结果延迟有状态说明 |

### 6.3 智能素材管理中心

| 需求编号 | 功能要求 | 验收要点 |
|---|---|---|
| FR-MAT-001 | 统一上传、预览和管理视频、照片与音频 | 文件类型或编码不支持时明确提示；保留原始媒体信息 |
| FR-MAT-002 | 从视频提取关键帧并切分场景 | 关键帧及片段保留源文件标识和时间范围 |
| FR-MAT-003 | 对片段进行画面内容识别 | 描述关联具体片段，可回到原始区间核对 |
| FR-MAT-004 | 完成语音识别与画面文本提取 | 转写、识别文本保留时间信息，支持纠错 |
| FR-MAT-005 | 生成人物、动作、场景和生活事件标签 | 标签可查看和修正；人物命名支持用户确认 |
| FR-MAT-006 | 提供多模态语义检索 | 自然语言查询返回相关素材及对应区间，并可预览 |
| FR-MAT-007 | 支持时间、人物、地点、事件和素材类型筛选 | 时间条件有明确解释；无元数据时不虚构地点或拍摄时间 |
| FR-MAT-008 | 进行画面质量评估和重复片段检测 | 问题标记可定位；重复检测不直接删除用户素材 |
| FR-MAT-009 | 支持分析状态查看、重新分析及标签更新 | 更新后关联索引保持一致，旧结果不与新结果混用 |

### 7.2 数据一致性要求

- 同一素材、故事节点和版本使用稳定标识，双端不得各自维护无法对应的副本。
- 素材时间范围不得超出源文件；时间轴调整后需检查字幕及声音依赖。
- 必留、禁用、锁定和用户确认状态均作为有来源的业务数据保存。
- 已提交的版本快照保持可追溯；修改通过新版本表达。
- 索引更新与素材删除应有明确状态，防止已删除素材被新任务再次使用。
- 文件不可用时保留可定位的缺失记录，不将失败伪装为分析完成。

### 7.3 数据集建设

拟建设五类场景、每类三个任务、每个任务至少二十段素材的初步数据集，共十五组任务、不少于三百段素材。每类一组用于开发、两组用于测试，总计五组开发任务和十组测试任务。

标注内容拟包括场景、事件、片段相关性、故事节点支持关系、自然缺口和部分构造缺口。自然缺口与人工移除素材形成的缺口分别报告。开发与测试按完整任务或事件隔离，原片、裁剪片和近重复片不得跨集合。

数据采集和标注规模均为计划值，实际报告须注明来源、有效样本量、分歧处理及未覆盖情况。

### 7.4 数据保护与保存

- 素材用于本项目处理的范围应向用户说明；不默认将用户素材用于训练。
- 对象存储和下载链接应有访问控制，敏感凭证不写入公开代码或客户端日志。
- 外部模型处理范围应可配置；必要时采用减少上传内容或本地处理的实现路径。
- 删除、保留与恢复策略分别覆盖原片、代理文件、索引、预览和导出文件。
- 音乐、旁白资源和外部素材记录来源及可用范围，交付前由用户复核作品内容。

### 9.1 接口类别

| 接口类别 | 需求 |
|---|---|
| 项目与权限接口 | 支持身份校验、项目访问、意图更新和版本读取 |
| 素材接口 | 支持上传、媒体信息、分析状态、片段预览、标签修改与删除 |
| 拍摄任务接口 | 同步清单、补拍要求、完成状态及新增素材关联 |

接口应返回稳定的业务标识和可解释错误；具有重复提交风险的操作应携带可去重的任务标识或请求标识。具体 URL、字段和错误码在接口设计阶段确定。

### 9.2 技术约束

- 移动端沿用 Flutter；Web 端沿用 Vue 3、TypeScript、Element Plus、Pinia 的方案方向。
- 后端沿用 FastAPI、LangGraph、PostgreSQL、Redis、Celery 和对象存储的方案方向。
- 分析与媒体工具候选包括 Whisper、OpenCV、PySceneDetect、Librosa、FFmpeg，模型候选包括 DeepSeek、Qwen、Qwen-VL 等。
- 文本语义向量可使用 BGE 等候选模型；直接图文匹配另行选择具有图文对齐能力的模型，不能混用能力假设。
- pgvector 或 FAISS 的选择应结合部署与检索测试，避免同时维护无必要的重复系统。
- 候选版本、授权条件、目标设备及模型能力在技术验证时核实，并记录实际配置。
- 模型输出不得直接作为任意脚本或命令执行；剪辑通过受控数据结构及校验器转换执行。

## 10. 非功能需求

### 10.1 性能目标与测量边界

下列数值沿用方案中的初步验证目标，并非实测结果或无条件承诺。目标应在 2026 年 11 月 21 日前结合设备与样例进行一次可行性复核，正式测试前冻结口径；后续如需变更，应保留原因及原目标。

参考创作工作负载为三十段素材、总时长约十分钟，输出一部一百二十秒、1080p 视频。测试报告须记录硬件、模型、本地或远程执行位置、网络、素材格式、队列负载及有效样本量。

| 编号 | 指标 | 初步目标及边界 |
|---|---|---|
| NFR-PERF-001 | 本地轻量摄影提示 | 分析耗时 P95 不高于 500 ms；单独记录采集、推送及展示耗时；不含云端语义分析 |
| NFR-PERF-002 | 故事板规划 | 素材分析完成后，规划处理耗时 P95 不高于 180 s；排队与用户等待分别记录 |
| NFR-PERF-003 | 局部规划 | 单次受控修改的规划处理耗时 P95 不高于 20 s，不含导出 |
| NFR-PERF-004 | 视频导出 | 在冻结的参考配置与编码参数下，处理耗时 P95 不高于 180 s；另报排队耗时 |
| NFR-PERF-005 | 音画同步 | 可测量样例中的偏移目标不超过 100 ms；检测方法与不适用情况需披露 |
| NFR-PERF-006 | 端到端体验 | 总耗时包含上传、排队、分析、规划、用户操作和导出，不能以局部耗时替代整体体验 |

局部重规划不代表最终 MP4 一定无需完整重新编码，性能报告须区分规划、分析与渲染三个阶段。

### 10.2 可靠性与恢复

| 编号 | 需求 | 验收方式 |
|---|---|---|
| NFR-REL-001 | 长任务有明确状态与超时处理 | 模拟接口超时、模型失败和媒体错误，能查看原因并继续处理 |
| NFR-REL-002 | 中断后可恢复或明确重启必要步骤 | 模拟 Worker 重启及网络中断，检查任务、文件和版本一致性 |
| NFR-REL-003 | 重复请求不产生重复业务结果 | 对上传完成、确认修改和导出提交进行重复调用检查 |
| NFR-REL-004 | 失败不破坏上一个可用版本 | 导出或修改失败后，原预览与历史版本仍可访问 |
| NFR-REL-005 | 数据有备份与恢复路径 | 至少验证一次数据库与关键项目文件恢复 |

### 10.3 可用性、可维护性与兼容性

- NFR-USE-001：初次使用者能够根据页面提示完成创建项目、上传、确认故事、预览和导出，先导测试记录阻断点。
- NFR-USE-002：AI 建议和确定性错误分别表达，用户可拒绝建议并继续创作。
- NFR-MNT-001：接口、数据结构、任务状态和核心配置有文档，依赖版本可复现。
- NFR-MNT-002：日志能关联项目、任务、版本与错误，不记录明文密钥。
- NFR-COMP-001：明确实际支持的浏览器、系统和移动设备；Android 与 iOS 分别记录构建及真机验证结果。
- NFR-COMP-002：对不同方向、帧率、分辨率和音轨参数的媒体提供兼容处理或明确限制。

### 10.4 资源与运行成本

记录模型调用量、计算耗时、内存或显存峰值、文件体积和存储占用。分析与渲染设置独立的并发上限，已完成的素材分析可按内容摘要和处理配置复用。

团队投入以三人、每人每周二十五至三十小时作为初步测算条件，六十天合计约六百四十至七百七十人时，须根据实际课程和可投入时间修正。费用按本轮周期另行核算，不沿用未经调整的六个月部署费用假设。

## 11. 验收与评价方案

### 11.1 功能验收

每项 FR 需求至少关联一个可重复的操作案例，记录输入条件、步骤、预期结果、实际结果、缺陷及对应提交版本。核心功能需同时覆盖正常与异常路径。

重点验收三条完整流程：

1. 拍摄流程：创作目标—拍摄清单—实时指导—拍摄缓存—上传—素材分析。
2. 创作流程：已有素材—事件检索—故事板—缺口判断—补拍回传—七角色协作—多轨成片。
3. 修改流程：审片问题—自然语言修改—影响范围—锁定校验—新版本—对比与恢复。

### 11.2 效果评价

| 指标 | 初步目标 | 测量要求 |
|---|---|---|
| 事件标签 macro-F1 | 不低于 0.75 | 冻结标签集，按场景报告有效样本量与错误类型 |
| 素材检索 Recall@5 | 不低于 0.80 | 至少四十条有人工相关集合的测试查询 |
| 缺口提示精确率 | 不低于 0.80 | 先确认故事需求，再人工核对素材；待确认项单独统计 |
| 缺口提示召回率 | 不低于 0.75 | 报告真实缺口分母，区分自然与构造缺口 |
| 必需故事节点覆盖率 | 用户处理缺口后不低于 0.90 | 不把用户主动取消的节点伪记为自动覆盖 |
| 锁定内容保护率 | 100% | 对规范化锁定字段及相关约束做前后比较 |
| 非目标片段变化率 | 0 | 以事先定义的允许影响范围为边界，出现变化即分析 |

这些数值属于待验证目标。故事连贯性、情绪表达和作品可接受程度需结合用户及独立评审，不能仅使用系统自评分。

### 11.3 用户测试

计划先进行五名用户的先导测试，修正主要操作问题，再视招募条件开展正式任务实验。正式实验拟招募十二名参与者，比较人工或模板剪辑、基础自动剪辑与本项目完整流程；每人使用不同且难度相近的素材完成三种任务，总计三十六次任务。

记录主动操作时间、机器等待、任务完成情况、补拍采纳、修改次数、满意度和再次使用意愿。采用平衡顺序减少学习效应，先导样本不混入正式样本。若实际样本不足，应报告真实规模与限制。

### 11.4 交付验收材料

- 源代码、依赖锁定信息、示例配置与部署说明。
- 双端可运行版本及目标设备支持说明。
- 本需求文档、架构与接口说明、数据结构说明。
- 完整功能检查表、测试报告、缺陷及限制清单。
- 已授权示例素材、数据集说明与标注记录。
- 三条完整流程的演示及对应版本信息。
- 项目计划书、使用说明、演示视频和答辩材料。

## 13. 风险、依赖与应对

| 风险或依赖 | 影响 | 应对及责任 |
|---|---|---|
| 三人六十天内双端与 AI 集成压力较大 | 功能集中到后期，测试不足 | 第一天明确接口，第一周跑通最小完整流程；全员每周集成，A/B/C 共同跟踪 |
| 目标设备、摄像头能力或构建条件未落实 | 实时指导与跨平台测试受阻 | 第一阶段核实设备与权限；A 主责，B 协助运行环境 |
| 模型质量或服务可用性波动 | 标签、故事与补拍判断不可靠 | 候选模型适配、来源校验、人工纠错、缓存和可恢复任务；C 主责 |
| 素材与故事关系不可靠 | 补拍误报、错选片段 | 先建立人工可核对的样例与节点映射，再扩大任务；C/B 协作 |
| 时间轴、字幕和声音依赖复杂 | 修改导致错位或范围扩大 | 统一时间表示、锁定校验、差异与版本恢复；B/C 主责，A 展示差异 |
| 异构素材与资源不足 | 预览或导出失败、等待过长 | 代理文件、格式校验、队列限流和渲染样例；B 主责 |
| 数据或用户招募不足 | 场景和效果无法充分验证 | 从校园任务早期采集，保留其他场景；实际规模如实披露；全员负责 |
| 需求频繁变化 | 接口返工和排期失控 | 使用需求编号、影响分析和修订记录；不通过删功能掩盖延期；全员评审 |

关键依赖：可靠素材分析先于自动覆盖判断；稳定节点关联先于补拍更新；可校验剪辑结构先于自动导出；版本与依赖关系先于可控局部修改。
