# 第二阶段实施大纲：素材证据链

> **计划窗口：2026 年 11 月 22 日—11 月 28 日（内部计划）｜状态：本机工程验证完成，独立验收待补（见[报告](reports/phase-2-report.md)）。** 第一阶段已用固定样例验证证据引用、覆盖和剪辑规则，也验证了媒体工具能处理测试文件。本阶段把输入从手工构造的元数据换成真实素材的分析产物；没有真实素材的端到端运行记录，不能宣称阶段通过。

## 1. 阶段目标与范围

**交付主链：** 授权视频上传 → 原片登记 → 媒体探测 → 切分与代表帧 → 转写、质量信号与关键词索引 → 搜索片段 → 跳转原片区间 → 生成可校验的证据输入。

- **最小交付**：Web 跑通真实视频的上传、分析、检索与预览；至少覆盖有语音、无音轨、损坏文件和无结果查询。有语音样例必须实际运行转写（本地或已配置服务）；协议夹具只验证接口，不算真实转写。
- **检索基线**：关键词基于该片段的时间戳转写、人工标签等可核对字段，支持按素材和源片内时间过滤。首版用轻量质量信号（如分辨率、曝光异常样本标记）和原片哈希精确重复提示；质量信号不等于可用性结论，不自动删除重复素材。
- **有余量再做**：OCR、照片/独立音频、近重复、向量或图文检索、带引用的模型事件标签探针。资源不足时记录延期；关键词基线不能写成已实现完整多模态检索，粗切片也不能写成镜头检测已达标。
- **本阶段不验收**：自动补拍闭环、自然语言局部重规划、生产版本发布、七角色编排和 Flutter 真机体验；Web 只需要能核对本阶段产生的证据。第一阶段远端商业模型和 Android 真机未验证，不阻塞本阶段离线工作，但不能据此宣称这些能力已通过。

需求追踪：最小交付涉及 `FR-MAT-001/002/004/006/007/008/009` 的子集；`FR-MAT-003/005` 仅作为标签探针跟踪，`FR-MAT-010` 的完整删除与影响提示不在本期。以[需求原件](requirements.md)为准，不将子集标记为整条需求完成。

## 3. 技术交接与关键约束

1. **复用现有基础。** 沿用 `stored_objects / assets / jobs / analysis_runs / segments` 的项目外键、媒体探针工具和 Job 六态。活动分析指针、产物持久化、幂等约束或任务恢复若需新字段，使用新迁移，不回改 `0001_foundation`。新字段同步共享契约与生成工件。阶段 2 的媒体资产不能写入 `phase_one_datasets`。
2. **统一溯源。** 候选至少携带 `project_id`、`asset_id`、`segment_id`、`analysis_run_id`、`in_ms/out_ms`、来源类型及排序依据。区间是原片毫秒半开区间 `[in_ms, out_ms)`，不得用代理播放位置或编造的时间戳替代。通过分析记录可查原片摘要、配置摘要和工具/模型版本。关键词命中或模型标签默认只是候选，不自动成为 `semantic_support=supported`。
3. **成功后才切换。** 任务可先用单 Worker，持久记录任务状态、耗时、失败码，复跑时可识别已完成产物；尚未成功发布的产物不可进入检索。对同一素材的结果发布做并发控制，避免旧任务晚结束覆盖较新的结果。失败不切换版本；新查询只取当前有效版本，历史快照固定引用旧分析，不偷偷替换。原片不可访问时明确报不可用。
4. **给阶段 3 可消费输入。** 交付带原片、片段、分析版本和内容摘要的候选快照与核验方法。用人工核对的真实片段绑定具体 `requirement_keys` 生成现有 `EvidenceManifest`，跑一次第一阶段覆盖内核作为交接测试；不捏造需求绑定、语义支持或质量结论。区间、版本和同项目关系由服务端校验，历史引用与当前检索分开处理。

详细契约见[详细设计 §6–7](design/detailed-design.md)、[数据库设计](design/database-design.md)和[共享契约](../packages/contracts/README.md)。

## 4. 创新怎么验

切片、转写、关键词搜索是基础能力。**本阶段要验证的是：系统给出的候选不仅能找到，还能回到原片核对，并能说明它来自哪一版分析。** 这是后续故事覆盖与补拍的输入保障，不等于已验证覆盖或补拍效果。

在同一批授权视频、相同转写数据、相同查询和固定 `K=5` 下，做一个小规模对照：A 组按原片级全文检索，候选只定位到文件；B 组按片段检索并提供原片区间和版本。运行前标注相关片段及可接受定位误差；给两组相同的定位时间上限，未定位记失败，不能无限回看。分别记录 Top-5 **素材命中率**（至少一条命中目标素材的有答案查询数 / 有答案查询总数）、从结果页到首次定位正确区间的用时、未定位次数。B 组额外报告 Top-5 **区间命中率**（至少一个候选落到正确素材且符合预先标注的区间匹配规则的有答案查询数 / 有答案查询总数），并按评测协议计算证据引用有效率及必需事实可核验率。无答案查询另报误返回情况；记录实际样本数、失败原因与 `N/A`，不只统计成功用时。对照是阶段内诊断，不替代[正式 A/B/C 与消融](evaluation.md)，也不作为行业首创或效果领先的证据。

## 5. 阶段验收清单

| 门槛 | 必须保存的证明 |
| --- | --- |
| G1 · 真实闭环 | 团队有权使用的实拍视频经正常接口完成上传 → 分析 → 查询 → 原片回看；带语音样例附实际转写记录；生成夹具单列 |
| G2 · 引用正确性 | 验收样例中返回的候选全部通过同项目、原片、分析版本和区间检查；越权、越界、跨版本混用样例被拒绝；无候选不能按 100% 计 |
| G3 · 失败与恢复 | 无音轨、坏文件、转写失败、无命中和重分析失败均有运行记录；重分析失败不切换，成功切换后旧快照仍可按旧版本核对；重启不重复发布 |
| G4 · 交接与复现 | 真实片段经人工核对后送入第一阶段覆盖内核；另一成员按提交号、数据版本、配置和命令复跑，保存对照结果与限制 |

报告记录上传/排队/处理耗时、转写来源与用量（如适用）、候选数量、失败原因、未做项和实际执行环境。素材登记与隔离按[数据准备指南](evaluation-data.md)执行。原片、完整私人转写、签名 URL、密钥和中间缓存不提交到 Git 仓库；提交脱敏记录、授权索引和摘要。若真实转写或引用闭环未过，只交付已验证的子集，不把夹具回放写成通过，也不让第三阶段的自动覆盖依赖未经验证的候选。
