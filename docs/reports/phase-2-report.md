## 3. 失败、授权与版本回放

- 派生无音轨视频成功，转写 `not_applicable`；合成坏文件失败为 `INVALID_MEDIA`。无答案查询返回空，没有伪造候选。
- 同项目重复上传返回同一资产且不追加任务。过期租约被重新领取，旧令牌写入被拒。另以无音轨衍生片验证进程重启：子进程领取并注入已过期租约后以状态 23 直接退出；首次启动 `sw_worker.media_jobs --once` 重领并发布 1 个片段，尝试计数为 2；第二次启动后结果及片段数不变。
- 以上进程重启检查现已并入 `verify_phase_two.py`。本机使用两段登记素材和本地模型复跑，新生成的 `worker_restart` 记录子进程退出码 `23`、两次尝试、发布 1 个片段，且第二次启动不更改分析结果或候选引用。该记录仍是开发复跑，不计成员独立签署。
- 对有音轨素材取消 ASR 配置后重分析，返回 `TRANSCRIPTION_NOT_CONFIGURED`，仍可检索上一成功版本；恢复模型后成功切换，新搜索只读活动版本，旧 `EvidenceManifest` 内容不变、旧代理仍可回看。
- 不同项目读取代理被拒，提交越界或错误版本被拒。自动测试还覆盖同资产混用新旧版本被拒、人工标签作用于搜索、延迟音轨时间对齐和迁移一致性。

## 4. 创新性：证据能定位、能复查

对照只检验机制差异：相同数据、查询、转写和 `K=5`。A 按原片全文检索，只返回文件；B 按片段检索，返回区间、分析版本和哈希。B 的有答案查询在同一原片上覆盖登记的开发锚点即记命中。

| 指标 | A：原片全文 | B：片段证据 |
| --- | --- | --- |
| Top-5 素材命中 | 3/3 | 3/3 |
| Top-5 区间命中 | 不适用；无区间 | 3/3 |
| 无答案误返回 | 0/1 | 0/1 |
| 候选可复核引用 | 不适用 | 3/3 |
| 人工首次正确定位时间与失败数 | N/A | N/A |
| 独立人工事实可核验率 | N/A | N/A |

B 返回区间分别为 `one-small-step [40,48)s`（`giant leap`）、`one-small-step [16,24)s`（`coming down a ladder`）、`buzz-descends [32,40)s`（`beautiful view`）。浏览器实测能定位到 `[40,48)s`，起点误差低于 150 ms，并校验下载清单的区间及需求编号。三个锚点是开发阶段根据转写对齐，不是独立标签。A 与 B 均命中文件，因此不能说 B 提高了素材命中率；没有人工计时就不能说定位更快。更不能从这一事件组推断检索领先或五场景泛化。

自动交接从该批真实分析数据导出清单，通过 `sw_ai.coverage.evaluate_coverage` 得到 `covered`。脚本模拟了复核表单的判断，**只证明数据可以交接以及规则能够消费，不是人工语义裁决**。下阶段如果要用该样例验证真实“故事覆盖”，须先由审阅人回看并确认绑定；不应把搜索命中自动升级成 `supported`。

另用 [Web 多清单交接入口](phase-2-acceptance.md#2-回看事实并交接) 读取实际浏览器下载的 `first-step` 清单：该要求被判定为 `covered`，未复核的 `ladder` 和 `buzz-view` 均为 `uncertain`，总覆盖仍为 `uncertain`。这次仍由自动化填写表单，只验证交接和缺证据不升级，不计 G4 人工确认。

预登记的非计时诊断复用 `giant leap` 的真实候选 `[40,48)s`，但把要求改为判断说话者的私下意图。脚本提交 `unknown` 后，即使 `search_complete=true`，引擎仍返回 `uncertain / semantic_unknown`：有 1 条候选但无合格或被选用的证据。它和「未检索到候选」是不同情况，不加入 A/B 分母或人工核验率。阶段 3 可用这一结果联调不确定性和清单契约，不得当作已确认事实。

A/B 人工验收另提供[同播放器计时包](phase-2-acceptance.md#可选同一播放器的本地计时包)，使用本轮分析中哈希匹配的代理；A 从 0 秒开片，B 从候选起点打开，观察员按独立冻结区间核对真实提交。已用实拍代理自动验证起播位置、超时与记录下载。计时包提交 `80e00e6` 的本机浏览器 5 项通过，其 [GitHub Actions `44728905525`](https://github.com/Cyrene-06/ShadowWeaveAI/actions/runs/44728905525) 的 core、Flutter 和 Android APK 构建均成功。模拟结果不纳入效能指标，表中的人工项仍为 `N/A`。
