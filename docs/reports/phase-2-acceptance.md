## 3. A/B 定位计时

1. 观察员复跑脚本后，先固化查询、Top-5、文件/片段候选和区间规则。候选从同批素材的相同时间戳转写生成。当前诊断用登记中的 `anchor_ms` 作为接受区间内的锚点；正式计时由独立标注员预先冻结目标区间，例如报告的毫秒时间点落在标注区间内，或者距边界不超过 1,000 ms。选定口径后两组不改动。参与者只看分配给自己的查询及候选，不看含答案的 JSON 或此表中的事实复核栏。
2. **A** 只给查询和脚本 `query_records.a_assets` 中按序的文件候选，从 0 秒手动定位。**B** 在素材工作区给同一查询的片段候选，可以点击“回看片段”定位。尽量使用同一设备和播放器、相同代理或相同编码媒体，清空之前的回看状态。
3. 结果首次可用时开始计时；参与者报告正确原片和时间点、观察员验证后停止。每条上限 60 秒；超时、错误定位和无命中分别记录。无答案查询单独记有无误返回和人员是否正确弃答，不纳入定位用时。至少采用互换分配：成员甲对一部分查询做 A、其余做 B，成员乙做相反分配；若同一人重复看同一素材，必须报告记忆偏差，不能声称盲测。
4. 分组报告 Top-5 素材命中、B 区间命中、引用有效率、人工确认事实数/应验证事实数、成功定位用时分布和失败/超时数。样本太少或未测则填 `N/A`；不把 Playwright 的跳转误差或接口延迟写成人工效率结果。

### 可选：同一播放器的本地计时包

计时包让 A/B 使用**同一批哈希核对过的代理、同一播放器和同一 60 秒上限**。A 保留文件候选顺序、从 0 秒打开；B 保留片段候选顺序、显示区间并跳到片段起点。此方案只比较**区间与跳转**，不把工作区 UI 的其他差异计入；实际工作区的播放、溯源和导出仍在 §2 核对。

观察员从仓库根目录运行。为本次实验选择新的 `artifacts/` 子目录，以免覆盖既有材料。分发前，让独立标注员先实际观看原片，确定可接受的原片和区间，再填写 `targets.json`。有答案题使用 `{"kind":"interval", "asset":"原片完整文件名", "in_ms":起点, "out_ms":终点, "tolerance_ms":容差}`，时间均为整数毫秒；容差为 0～1,000 ms。判定区间为原片范围内的 `[in_ms - 容差, out_ms + 容差)`。无答案题使用 `{"kind":"no_answer"}`。顶层键是 `first-step`、`ladder`、`buzz-view` 和 `no-answer`。不要以候选区间替代独立标注。
